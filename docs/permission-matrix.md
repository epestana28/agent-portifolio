## 1. Finalidade e regra de bloqueio

Este documento cumpre a "Matriz obrigatória" da secção 8 da especificação. Tem uma linha por operação. Cada linha indica API e versão, modo, identidade, permissão exacta, grant no recurso, papel administrativo, licença, evidência documental e teste negativo.

Regra da especificação: qualquer linha incompleta bloqueia a implementação real dessa operação. Uma linha fica INCOMPLETA quando pelo menos um dos campos não está verificado em documentação oficial. Os campos em falta ficam referenciados por códigos L01 a L18, listados na secção 6 com a forma de desbloquear.

Resultado desta versão: nenhuma linha está completa. Todas as linhas estão INCOMPLETA. Por isso, nenhum adaptador real para Entra, Graph ou Exchange pode ser implementado a partir deste documento. A fase B (fatia local em .NET 8) usa adaptadores simulados, assinalados como simulação, e continua a ser o limite do que existe. As fases C, D e E não foram executadas e o Bicep nunca foi aplicado.

A coluna "Evidência" cita páginas de Microsoft Learn. Todas foram verificadas a 2026-11-11. Prefixo dos URL quando abreviado: `https://learn.microsoft.com/en-us/`.

Legenda:

- Verificado: texto lido na página.
- Inferência: conclusão a partir de textos verificados. Não está escrita na documentação.
- NÃO VERIFICADO: a documentação lida não o afirma, ou a página só foi lida por excerto.
- Identidades: "agente" (o runtime do agente, que nunca recebe a credencial de dados), "executor" (identidade de execução separada por agente, `ExecutorObjectId`, detém a credencial de dados), "identidade de controlo" (serviço de controlo privilegiado, nunca usada pelo runtime do agente) e "operador" (pessoa com papel, via API de controlo ou centro de administração).

## 2. Contradições em destaque

### Contradição A. Menor privilégio de leitura com Selected

Verificado. As quatro páginas de leitura (`drive-list`, `driveitem-list-children`, `driveitem-get`, `driveitem-get-content`, todas v1.0) não listam nenhum scope `*.Selected` na tabela de permissões de aplicação. A permissão de menor privilégio que indicam é `Files.Read.All`. Essa permissão tem âmbito de todo o tenant e destrói o objectivo do projecto.

Verificado. A visão geral de Selected afirma o contrário: os scopes Selected dão acesso a estes recursos pelos caminhos `/drives/{driveid}/items/{itemid}` e `/sites/{siteid}/lists/{listid}/items/{itemid}`, e o papel `read` é "Read the metadata and contents of the resource". Fonte: `https://learn.microsoft.com/en-us/graph/permissions-selected-overview`.

Inferência. Pelo modelo documentado, a permissão de menor privilégio para o MVP é `Sites.Selected` (ou `Lists.SelectedOperations.Selected` para uma só biblioteca), em modo aplicação, com papel `read` atribuído no recurso.

Decisão de desenho enquanto não houver teste em tenant: não usar `Files.Read.All`, `Sites.Read.All` nem `Sites.ReadWrite.All` para contornar a dificuldade (especificação, secção 8). Se um endpoint recusar o token Selected, a operação fica bloqueada e a lacuna fica registada. Não se esconde com simulação.

### Contradição B. Permissão para conceder em lista e item

Verificado. A visão geral de Selected exige, para atribuir permissões numa lista, `Sites.FullControl.All`, `Sites.Selected` com papel FullControl, ou `Sites.Selected` com papel Owner. Para item e ficheiro acrescenta `Lists.SelectedOperations.Selected` com FullControl ou Owner. Fonte: `https://learn.microsoft.com/en-us/graph/permissions-selected-overview`.

Verificado. A referência da API (`list-post-permissions` e `listitem-post-permissions`, v1.0 e beta) indica como menor privilégio `Sites.ReadWrite.All`, com `Sites.FullControl.All` e `Sites.Manage.All` como superiores, e não lista nenhum scope `*.Selected`. Fontes: `https://learn.microsoft.com/en-us/graph/api/list-post-permissions?view=graph-rest-1.0` e `https://learn.microsoft.com/en-us/graph/api/listitem-post-permissions?view=graph-rest-1.0`.

As duas páginas não podem ser ambas verdadeiras. Só um teste em tenant decide. Decisão de desenho até lá: assumir o requisito mais forte (visão geral). Nota de risco: `Sites.ReadWrite.All` seria uma permissão de escrita em todo o tenant, o que é inaceitável para uma identidade de concessão.

### Contradição C. Assimetria entre criar e remover grant no site

Verificado. Criar permissão no site aceita modo delegado e aplicação (`Sites.FullControl.All`). Remover permissão no site só aceita aplicação ("Not supported." em delegado). Fontes: `https://learn.microsoft.com/en-us/graph/api/site-post-permissions?view=graph-rest-1.0` e `https://learn.microsoft.com/graph/api/site-delete-permission?view=graph-rest-1.0`.

Consequência verificada: revogar o grant no site exige uma identidade de aplicação com `Sites.FullControl.All`. A alternativa documentada é revogar o consentimento no Entra, que corta o acesso a qualquer lista em que o scope tenha sido concedido.

### Outras divergências que afectam a matriz

- Blueprint contra blueprint principal (C6 da pesquisa): a lista "Agent blueprints" é descrita como blueprints numa página e como blueprint principals noutra. Afecta I02.
- Significado de `accountEnabled` (C10): a referência Graph diz "no users are able to sign in to this app", as páginas de administração dizem "block its access and token issuance". Afecta I01 e I02.
- Validade do URL de download pré-autenticado: "might expire within minutes" numa página e "1 hour" noutra. Usar 1 hora como pior caso. Afecta M04.
- Versão Graph de `isDisabled` em application: desactivar em beta, reactivar em v1.0, na mesma página (C7). Afecta S01 (ver a nota sobre `isDisabled` na secção 5).

- I02: a política Conditional Access de bloqueio tenant-wide (três políticas) não altera objectos. Usa Graph beta e tem requisitos de licença com divergência entre páginas. Não é uma linha desta matriz porque não é a acção de contenção por agente. Fica referida na avaliação do ambiente.
- S01, nota sobre `isDisabled`: a página de desactivação de application (`isDisabled`) usa beta para desactivar e v1.0 para reactivar, com âmbito global. É um interruptor independente de `accountEnabled`. Não está incluído nesta matriz por falta de verificação da versão do recurso. Fonte: `https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/deactivate-app-registration`.
- U01: a documentação diz que, ao desactivar e revogar, "the user loses access when the access token expires". CAE é a única via documentada para revogar access tokens de aplicações compatíveis.
- E01: `Application Mail-Advanced.ReadWrite.All` é a alternativa mais próxima. A diferença prática face a `Mail.ReadWrite` não está explicada na página. Application Access Policies são legacy e não se usam em implementação nova (especificação, secção 8).
- E01: `Test-ServicePrincipalAuthorization -Resource <caixa>` devolve `InScope`, mas "excludes permissions that might be granted separately in Microsoft Entra ID".
