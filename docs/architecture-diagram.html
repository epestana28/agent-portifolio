Agent Portifolio, Three-Plane Architecture

Workflow: Agent Request
1. Agent sends JWT plus request to POST /actions
2. Executor validates token, checks revocation epoch
3. AuthZ Engine makes deterministic decision (no external I/O)
4. If allowed, call external service with re-validation before call
5. Record decision plus audit event (atomic transaction)
Workflow: Suspension
Control Plane (atomic single transaction):
1. Operator calls POST /agents/{id}/suspend
2. Change state to Suspended
3. Increment revocation epoch (invalidates all capabilities)
4. Write containment operation to outbox
5. Record audit event

Worker Plane (asynchronous):
6. Containment Orchestrator picks up from outbox
7. Runs 4 adapters in parallel: disable identity, remove grants, isolate runtime, probe tokens
8. Each step records honest state: Executed, Failed, or Unknown
9. Summary: VerifiedScoped (all verified) or Partial (any Unknown)
Key Principles
✓ Deterministic Authorization: No I/O in the AuthZ Engine. Same inputs always produce the same decision.

✓ Three-Transaction Pipeline: TX1 (admit), TX2 (execute), TX3 (audit). Each can fail independently, state stays consistent.

✓ Fail-Closed: If state unavailable, respond 403 Denied. Never cache positive decisions.

✓ Ledger is Native: SQL Server LEDGER=ON, not custom blockchain. UPDATE/DELETE rejected by the engine.

✓ Honest Containment: Each external step has an honest state. Unknown if uncertain, never assume success.

✓ Atomic Suspension: Revocation epoch, containment, and audit all in one TX.
What's Simulated (Today)
All external service calls (Entra, Graph, SharePoint) run against an in-memory simulation with fault injection capability. This proves the control logic works, it is NOT evidence of how Microsoft services behave. Phase C will run against a real tenant.
